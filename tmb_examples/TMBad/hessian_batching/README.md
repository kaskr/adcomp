# Opt-in compressed Hessian batching: draft runtime contribution

After installing this TMB version and recompiling/loading a TMBad model, opt in before constructing a new objective:

```r
TMB::config(tmbad.sparse_hessian_compress = TRUE,
            tmbad.sparse_hessian_batch_width = 8L, DLL = "mymodel")
```

The new setting defaults to 0 (original behavior). Supported nonzero widths are 2, 4 and 8. Batching requires compression to be enabled. Unsupported groups fall back to the original compressor. Changing settings does not rebuild existing derivative tapes. This is a proposed API for review.

Exact built-in operator identities replace name-based recognition. Arithmetic variants that suppress derivatives are accepted only when the suppressed input has no tape-input dependency. The implementation uses existing TMBad compression and vector operators; it is not a replacement for those mechanisms.

## Checks

From the repository root, with clang and RcppEigen installed:

```sh
python3 tmb_examples/TMBad/hessian_batching/run-sanitizers.py \
  --eigen-include "$(Rscript --vanilla -e 'cat(system.file("include", package="RcppEigen"))')" \
  --output /tmp/tmb-batching-sanitizers
```

On macOS, select Apple clang explicitly with `--compiler /usr/bin/clang++` if the default compiler uses an incompatible SDK.

The output directory must not exist. This instruments TMBad itself with AddressSanitizer and UndefinedBehaviorSanitizer, running 672 analytic sparse/derivative cases, 320 in-place source retapes and 640 copy/destruction checks. The analytic tests check through fourth derivatives, including sparse-index remapping, partial groups, custom operators and nested atoms. Leak detection is disabled; no leak-freedom claim is made.

After installing this branch, run the R-facing configuration check with that installation first in `.libPaths()` (for example via `R_LIBS_USER`):

```sh
Rscript --vanilla tmb_examples/TMBad/hessian_batching/config-test.R \
  tmb_examples/TMBad/hessian_batching/config-test.cpp /tmp/tmb-batching-config
```

This checks the default, finite objective/gradient agreement across four widths, and rejection of invalid widths. It requires a working TMB C++ compiler. The output directory must not exist.

## Evidence and limitations

On a pinned FIMS Laplace workload (139 fixed, 119 random parameters), three fresh runs of 100 identical changed-point evaluations found median elapsed 108.15 s with batching disabled versus 37.85 s at width 8. Accumulated gradient time fell from 58.164 s to 17.678 s, while peak RSS increased from 584.56 to 912.52 MiB. Objectives and current random-effect modes matched exactly; maximum gradient difference was 3.05e-11. These macOS arm64 measurements used the preceding hardened implementation with an experimental environment switch. The present configuration-wiring patch has correctness/sanitizer checks, not a new performance claim. Results are model-specific and are not full optimizer fits.

The tested runtime uses TMBad `ad_aug`. Other AD instantiations, concurrent use, active-recording exception paths, compiled tapes and other platforms remain unverified. Tests preserve old derivative tapes as snapshots when source tapes are retaped; they do not assume derivatives update automatically.

TMBad headers in this repository are autogenerated. The maintained source/generator location has not yet been established; confirm it with the maintainer before upstream integration. This branch is a reviewable draft against the distributed files. The separate existing-compression documentation contribution is not included.
